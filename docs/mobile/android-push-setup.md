# Уведомления Android без истории

Статус на 10.11.2026: Firebase-проект `cryptogoblin-2b0ab` создан, Android-приложение зарегистрировано. Серверная отправка сообщений P2P и гаранта подключена, APK 1.1.0 опубликован. Проверены серверная аутентификация FCM, регистрация и отвязка устройств. Проверка реальной доставки на телефон остаётся обязательной после установки APK.

Готовая настройка не требует повторения шагов создания проекта ниже. Закрытый ключ отдельного отправителя находится вне публичного каталога сервера; в Android-конфигурации есть только клиентские настройки Firebase.

Для получения уведомлений при закрытом приложении используем Firebase Cloud Messaging (FCM). Firestore, Realtime Database и отдельный экран истории уведомлений для этого не нужны. На сервере сохраняются только привязки устройства к пользователю и токены доставки, а не история текста уведомлений. FCM может временно удерживать сообщения для доставки; это не режим отсутствия хранения у провайдера.

Без push-сервиса можно показывать сообщения через существующее соединение с сайтом только во время его работы. Это не заменяет уведомления при закрытом приложении.

## Что сделать владельцу

1. Открыть https://console.firebase.google.com/ и нажать «Создать проект». Название: CryptoGoblin. Google Analytics для этой задачи можно не подключать.
2. В проекте нажать значок Android («Добавить приложение»). В поле имени пакета ввести `ru.cryptogoblin.app`. Это существующий идентификатор приложения, менять его не нужно.
3. Зарегистрировать приложение и скачать `google-services.json`. Положить файл в `android/app/google-services.json` проекта Goblin. Файл относится к конфигурации Android, он не заменяет серверные учётные данные.
4. Открыть настройки проекта через шестерёнку, затем «Сервисные аккаунты» и Firebase Admin SDK. Создать новый закрытый ключ для серверного отправителя. Если политика Google Cloud запрещает создание ключей, не отключать её самостоятельно: согласовать другой способ серверной аутентификации.
5. Передать серверные учётные данные через защищённый канал или разместить на сервере вне публичного каталога с доступом только владельцу процесса. Не отправлять ключ в чат, не добавлять в Git, APK или frontend.

## Реализовано в коде; что проверить на устройстве

- Установить совместимый с Capacitor 7 пакет `@capacitor/push-notifications@latest-7` и синхронизировать Android-проект.
- Добавить запрос разрешения на уведомления, регистрацию устройства и отдельный монохромный значок уведомлений.
- Сделать авторизованную привязку токена устройства к пользователю, обновление токенов и отвязку при выходе. Не допускать отправки уведомлений предыдущего аккаунта после смены пользователя.
- Подключить серверную отправку FCM к согласованным событиям. Не записывать текст сообщений или секреты в журнал. Удалять недействительные токены.
- В уведомлениях на экране блокировки использовать нейтральный текст без баланса и содержимого приватной переписки. По нажатию открывать нужную сделку только после проверки авторизации и доступа.
- Установить обновлённый подписанный APK 1.1.0 с `/download`. Одного обновления сайта для добавления нативного push-плагина недостаточно.
- Проверить реальным устройством: приложение открыто, свернуто, закрыто, разрешение отклонено, выход из аккаунта, смена аккаунта и нажатие на уведомление. Ограничения Android и принудительная остановка могут препятствовать доставке.

Официальная документация Capacitor 7: https://capacitorjs.com/docs/v7/apis/push-notifications
