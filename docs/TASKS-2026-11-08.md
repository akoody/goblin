# Пачка задач: состояние исходников на 8 ноября 2026

Готовые изменения опубликованы 8 ноября 2026; подробности и проверки production — в RELEASE-2026-11-08.md. Применены миграции 037–039. Старые применённые миграции не менялись. Незавершённое создание TRC-20 и отложенные владельцем внешние заявки/новые торговые комиссии не включались.

## Что изменено в этом заходе

Котировки разделены на спот и USDT-фьючерсы. Binance использует отдельный futures API, резервный Bybit сохраняет правильную категорию рынка. У контрактов 1000SHIB/1000PEPE/1000BONK/1000FLOKI цена делится на 1000, а количество базовых токенов в стакане умножается на 1000. Кэши разделены, параллельные запросы объединяются, данные старше минуты при отказе обоих источников не выдаются за актуальные. Поздний ответ предыдущего рынка не меняет текущую цену ордера. Маленькие цены мемкоинов больше не округляются до 0 при заполнении поля цены.

Реальные заявки через API и новые комиссии торговли **пропущены по решению владельца**. Ни ордера, ни деньги при проверках не отправлялись.

При создании категории в админке маркета выбираются «Аккаунты», «Услуги» или оба раздела. Вместо набора лишних шаблонных подкатегорий создаётся только выбранное. Для новой произвольной подкатегории также явно выбирается раздел; серверные ограничения пользователя учитывают это поле. Старые разделы и объявления не удаляются, открытые заказы и чаты сохраняются. Новая категория доступна в полном списке для добавления подкатегории: прежнее ограничение 24 элемента убрано. Успех, неправильные данные и дубликаты отображаются в админке.

В основных меню вместо «Проекты» теперь аккаунты и услуги; старые маршруты оставлены для совместимости с существующими сделками. Задачи продвижения не удалены из данных.

Первые три категории в каждом разделе показываются по общей посещаемости всех пользователей, остальные — строго по алфавиту, без дублирования популярного блока. При поиске остаётся обычная алфавитная выдача. Пока посещений нет, искусственного топа нет. Повтор одного посетителя в одной категории/разделе за сутки не увеличивает счётчик; одновременные запросы тоже не удваивают его. Учёт ведётся после реального открытия страницы, не при Next.js prefetch. Для входящих пользователей используется ID, для гостей — HMAC от адреса и User-Agent. Сырые IP не сохраняются; временные идентификаторы дедупликации удаляются через короткий срок, общие счётчики сохраняются. Это базовая защита от обновлений страницы, не полноценная антибот-система.

## Как сейчас происходит торговля

Binance/Bybit дают справочные цены, график и стакан. Они не являются контрагентом исполнения Goblin. Заявки сопоставляются во внутренней книге `trading_orders`: по цене, времени и ID, без сделок пользователя с самим собой.

При спотовой покупке резервируется валюта котировки, при продаже — продаваемый актив. На исполнении одна SQL-транзакция списывает и зачисляет валюты участникам, снимает соответствующие резервы и записывает исполнение. Например, продажа 1 BTC за 100 USDT означает внутреннее уменьшение BTC продавца и USDT покупателя, затем увеличение BTC покупателя и USDT продавца. Это условный пример механики, не рыночная цена. Между депозитными адресами в этот момент блокчейн-перевод не выполняется.

Фьючерсы сейчас тоже внутренние: резерв маржи, позиции, реализованный PnL, funding и сопоставление с внутренними ордерами. Это не открытая позиция Binance/Bybit и не доказательство внешнего обеспечения обязательств. Финансовую модель фьючерсов нельзя считать проверенной только потому, что загружается внешний график. Внешнее исполнение и новые тарифы не включались.

Без внутреннего баланса возможна другая архитектура — заявки на личных биржевых аккаунтах пользователей через их API-доступ. Но это не превращает текущий custodial-код в такую систему одним переключателем и не решает автоматически сбор собственной комиссии. Выбор и реализация внешнего исполнения отложены владельцем.

## Кошелёк и AML простыми словами

1. У каждой поддерживаемой валюты есть свой сетевой адрес и внутренний баланс. Отправлять нужно именно в указанной сети. Баланс сайта — учёт обязательств биржи перед клиентом; он не обязательно равен остатку одного персонального адреса после внутренних сделок и реферальных начислений.
2. Сервер находит внешнее поступление, проверяет получателя/сумму/подтверждения и создаёт запись депозита. Пока проверка не завершена, поступление не становится доступным балансом. Перезагрузка страницы не создаёт второе зачисление.
3. Для настроенных поддерживаемых сетей Safio проверяет адрес отправителя. Автоматическое зачисление допускается только при завершённой проверке, низком риске, полном покрытии и разрешающем результате. Это не полноценное расследование всей цепочки транзакции: сейчас используется продукт `screen` по адресу.
4. Повышенный риск, неполные результаты, неподдерживаемая сеть и ошибки не разрешают автоматическое зачисление. Они остаются для разбора. Высокий риск не запускает автоматический возврат отправителю. Администратор сверяет данные и внешний отчёт; менять только подпись статуса для обхода проверки нельзя.
5. Bitcoin имеет отдельный явно включаемый режим без AML только для новых поступлений. Тогда сохраняются сетевые подтверждения и проверка покрытия, но происхождение не проверяется; история помечается «AML не выполнялся». Старые блокировки этим переключателем не снимаются.
6. При успешном зачислении удерживается комиссия депозита в той же валюте, остальное попадает клиенту. Тариф и минимальная сумма определяются политикой депозита; текущие настройки production в этом заходе не читались. Для других валют применяется зафиксированный курс на зачисление. Реферальная доля берётся из комиссии биржи, а не повторно из денег клиента.
7. «Всего» — зачисленный учётный баланс. «В резерве» — часть, заблокированная сделками, ордерами или выводами. «Доступно» — остаток, который можно использовать. Незачисленный депозит на проверке не является доступной частью.
8. Казна показывает заработанные комиссии; это отдельный учёт от балансов клиентов. Консолидация собирает только подтверждённую собственную долю биржи, не клиентские остатки, AML-удержания и не обеспечение реферальных обязательств. При несоответствии адресного покрытия сбор останавливается.
9. Внешний вывод требует доступных средств, подключённого сетевого исполнителя и оплаты сетевых расходов. Сохранённый адрес автовывода сам по себе не отправляет деньги. Внутреннее реферальное зачисление тоже не переносит обеспечение между адресами; ограничения описаны в документе по реферальным начислениям.

## TRON: выбранная схема, ещё не готовый запуск

Первый этап — обычный TRC-20 с фиксированным выпуском, без дополнительного mint, администраторской заморозки, скрытого налога и автоматического пула. Создание пула и внесение ликвидности — отдельные действия с отдельной сметой и согласием пользователя. Ликвидность не должна автоматически списываться под видом обязательной сетевой комиссии выпуска токена.

Перед включением нужны совместимый с TVM проверенный контракт/компилятор, расчёт лимита сетевых расходов, резерв TRX, идемпотентное подписание, сохранение транзакции до отправки, обработка неоднозначного broadcast и подтверждённого receipt, учёт фактических расходов/тарифа, выдача токена в кошельке и проверка неуспешного запуска. В этой пачке эти компоненты не добавлены, деньги не списывались.

Документация провайдеров: [Binance USD-M Market Data](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data), [Bybit Tickers](https://bybit-exchange.github.io/docs/v5/market/tickers), [TRON deployment](https://developers.tron.network/docs/deploying).
