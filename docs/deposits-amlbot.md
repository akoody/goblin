# Депозиты, комиссия и AMLBot

По умолчанию минимальный депозит — эквивалент 5 USDT, комиссия — эквивалент
2 USDT с каждого отдельного пополнения. Комиссия редактируется в админке
«Кошелёк и AML» (0–4,99, чтобы оставаться ниже минимального депозита).
Старые пополнения и балансы не пересчитываются. Тариф фиксируется при обнаружении
транзакции, курс — при её зачислении. Расчёт идёт в Decimal с округлением комиссии
вверх до точности сети. USDT учитывается по номиналу 1; это не обмен валют.

Комиссии поступают в общий внутренний баланс администраторов в валюте депозита.
Это бухгалтерский учёт обязательств, не новый адрес блокчейна и не автоматический
перевод монет. Вывод казначейства и свип пользовательских адресов не реализованы.
Не пытайтесь вывести одни и те же монеты как средства пользователя и казначейства.

Новые подтверждённые блокчейн-поступления создают `PENDING_AML`, но не увеличивают
доступный баланс. Подтверждение возможно только после внешнего отчёта и решения
администратора; высокий/неизвестный риск нельзя подтвердить. Без отчёта, при сбое
курса, повторном запросе или сумме ниже минимума зачисления нет. Мелкий депозит
физически нельзя запретить в блокчейне: он удерживается для разбора, не уничтожается
и не переводится автоматически обратно отправителю. Заблокированные средства
также не возвращаются автоматически. Юридический порядок разбора требует отдельной
политики бизнеса; техническая блокировка не равна полной AML-compliance.

BTC/ETH в имеющемся проекте не имеют внешнего депозитного процессинга. Их расчёт
комиссии поддержан и проверен, но этот релиз НЕ включает отсутствующие сканеры и
не обещает принимать BTC/ETH. Рабочие сканеры сейчас относятся к USDT/TRX (TRON).

## Что сделать в AMLBot

1. Открыть https://amlbot.com/ и перейти в бизнес-продукт AML/KYT для проверки
   криптовалютных транзакций. Не выбирайте только KYC-проверку документов.
2. Открыть официальную документацию API:
   https://docs.amlbot.com/webApi/introduction . Она направляет за Access ID и
   Access Key в поддержку https://t.me/amlbot_support_bot . Ссылка также есть
   в документации; проверяйте, что переходите именно от официального сайта.
3. Написать: «Нужен бизнес API для проверки входящих депозитов криптобиржи
   cryptogoblin.ru: USDT TRC-20 и TRX, затем BTC и ETH. Нужны transaction screening,
   отчёты с категориями риска, Access ID/Key, актуальный API-контракт и стоимость».
4. Согласовать аккаунт, поддерживаемые сети, стоимость/лимиты и оплатить проверки
   в интерфейсе провайдера самостоятельно. Этот релиз ничего не покупает.
5. Передать актуальную API-документацию и идентификатор аккаунта. Ключ установить
   только на сервере через защищённый канал, не во frontend и не в репозитории.
6. После получения доступа подключить адаптер, проверить подпись/сопоставление
   ответа с сетью, хешем и получателем, обработать pending/error/retry и проверить
   тестовые кейсы. Затем согласовать пороги и категории блокировки бизнеса.

Автоматические запросы AMLBot и автоматическое «чисто» НЕ включены без аккаунта,
ключа и проверки актуального контракта провайдера. Подготовлены очередь, привязка
к событию сети, ручной разбор отчёта, единственная точка атомарного зачисления и
казначейство. Не подменяйте отсутствие ответа провайдера разрешением зачисления.
Номер отчёта вводит администратор; приложение не подтверждает его подлинность
автоматически. В финансовом интерфейсе это явно обозначено.

Выкладка 14.10.2026: финансовые таблицы сохранены в защищённом SQL-backup;
старые 10 блокчейн-депозитов остались зачисленными без ретроактивных комиссий.
В серверной проверке одноразового аккаунта повторное/параллельное подтверждение
зачисляет только один раз; нет зачисления без отчёта или ниже минимума. QA-аккаунт,
транзакции и доход тестовой комиссии удалены. Административные API проверены
реальными read-only запросами; UI дополнительно проверен с имитированными
ответами API — эти два уровня проверки не смешивать.

## Проверки

`npm test` в backend — чистые проверки точности/минимума/правил отчёта.
`DEPOSIT_DB_CHECK=1 node scripts/check-deposit-compliance.js` — opt-in сценарий
с одноразовым QA-аккаунтом, искусственным депозитом только этого аккаунта и
очисткой в finally, без отправки монет или обращения к AMLBot.

Миграция 016 добавочная. Сохраняйте совместную резервную копию wallets,
blockchain_deposits, deposit_reviews, admin_treasury и ledger. Откат старого
сканера после накопления незачисленных депозитов опасен: он не знает очередь.
Не откатывайте денежную логику без отдельной сверки обязательств.
