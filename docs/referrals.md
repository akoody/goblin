# Реферальные приглашения

Профиль → «Реферальная система»: персональная ссылка `/signin?ref=GBL…`.
Админка → «Приглашения»: поиск по пригласившему, email, ID и коду;
выдача/копирование ссылки, регистрации, суммы по валютам, список приглашённых.
Существующие коды сохраняются. Новая выдача ссылки не меняет пригласившего
уже зарегистрированных аккаунтов. Привязка `users.referred_by` создаётся только
в транзакции регистрации и не изменяется при входе по чужой ссылке.

Первая корректная ссылка сохраняется в браузере на 30 дней; переходы внутри
основного сайта не теряют код. После успешной регистрации сохранение очищается.
Ручное поле кода позволяет пользователю исправить выбор. На другом устройстве,
после очистки хранилища или в браузере, запрещающем сохранение, автоматическая
долговременная атрибуция не гарантируется. Это учёт регистраций, не уникальных кликов.

Суммы берутся исключительно из `blockchain_deposits`, связанных через кошелёк
с приглашённым аккаунтом. Внутренние переводы, сделки, рублёвый маркет и ручные
изменения баланса не учитываются. Подтверждённая сумма — gross, комиссия — fee,
зачислено — net. Незавершённые AML и заблокированные поступления показаны отдельно.
Старые зачисленные blockchain-депозиты без review учитываются по полной сумме
и с нулевой комиссией. Нет суммирования разных активов, округления через Number,
ретроактивной привязки или изменения реальных балансов.

Оба списка постраничные, по 25 аккаунтов. Все суммы пригласившего включают
всех его приглашённых, а не только страницу деталей. Доступ к финансовым
подробностям и email — только у администратора с серверной проверкой полномочий.
Это статистика пополнений, не начисление реферальных вознаграждений.

Проверки: `npm test --prefix backend`, `node scripts/check-referral-attribution.mjs`,
`npm run build`. Автоматические проверки с подставными ответами не заменяют
проверку SQL на MySQL и реальной регистрации на целевом сервере.
