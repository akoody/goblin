# Объявления, сделки и просмотр гаранта

Объявления и «Мои сделки» используют общий адаптивный список. Поиск по номеру,
статусу, цене (объявления), участнику и номеру ордера (сделки); фильтры по статусу
и покупке/продаже, по 20 результатов на страницу. Номер копируется отдельной
кнопкой. Показываются остаток, лимиты, способы оплаты, дата, участник и сумма.
Даты берутся из created_at с поддержкой прежнего createdAt. ID участников
сравниваются как строки, чтобы данные MySQL и JWT не давали пустые списки.

Для активных объявлений доступны пауза, возобновление и снятие с подтверждением.
Повторные нажатия блокируются до ответа API. Исполненные и отменённые объявления
не получают кнопок повторной активации. После ошибки список не выдаётся за пустой.
Логика резервирования, комиссий и закрытия P2P-сделок этим релизом не меняется.

## Цена графика и стакана

Нажатие/касание графика выбирает ближайшую отображаемую точку по горизонтали и
подставляет её close в лимитный ордер. Наведение показывает цену и время.
Поддержаны стрелки, Home/End, Enter и пробел. Исходная строка цены сохраняется
без округления при подстановке. Историческая цена не означает доступную цену
исполнения. Стакан также подставляет цену и показывает подтверждение; на мобильном
экране форма прокручивается в видимую область. Нажатия НЕ отправляют ордер.

## Админка

В основной админке есть вкладка «Гарант» и прямая ссылка
`/admin?section=guarantor`. Показаны только ESCROW-сделки. Поиск и фильтрация идут
на сервере до LIMIT, 25 записей на страницу, споры приоритетны. Ссылка открывает
существующий защищённый просмотр условий, участников, переписки и истории.
Существующие решения по спорам не менялись, просмотр сам ничего не списывает.
Новый GET `/api/commerce/admin/escrow` проходит серверную проверку администратора,
не кешируется и использует только SELECT. Новых таблиц и миграций нет.

Проверки: `npm test --prefix backend`, `node scripts/check-chart-points.mjs`,
`node scripts/check-p2p-usability.mjs`, `npm run build`. Интерфейс проверяется
с заполненными изолированными данными; изменения объявлений в тестах перехвачены,
реальные заявки не создаются. Требуется отдельная проверка нового API на MySQL
и прав доступа после выкладки.

Выложено 16.10.2026 на cryptogoblin.ru. Backup:
`/root/goblin-backups/pre-p2p-usability-20261016.tar.gz`.
33 backend-теста и 40 проверок заполненного интерфейса на пяти ширинах прошли;
те же 40 сценариев повторены на опубликованных assets с перехватом мутаций.
Новый список проверен на реальном MySQL и публичном API, включая поиск,
статусы, страницы, no-store и запрет доступа для гостя/обычного пользователя.
Существующие административные read-only проверки также прошли. Миграций нет.
# Администрирование сделок гаранта

В `/admin?section=guarantor` сделки фильтруются группами «Ожидают», «Действуют», «Закрыты»; группа «Новые сообщения» показывает сообщения участников после личной отметки администратора о прочтении. При открытии чата отметка двигается до последнего сообщения.

Для сделки с резервом администратор указывает причину и выбирает единственный исход: зачислить USDT продавцу или вернуть покупателю. В ожидании резерва администратор может отменить сделку с причиной. Все изменения статуса, баланс и ledger записываются в одной транзакции. Перед включением новой версии применить миграцию `017_commerce_admin_message_reads.sql`.

## Комиссия гаранта

Начальная ставка — 5%. Она показывается на публичной странице гаранта, а при создании сделки копируется в саму сделку, поэтому изменение тарифа администратором влияет только на новые сделки. При успешном завершении продавцу зачисляется сумма за вычетом комиссии; комиссия добавляется к общему USDT-балансу администраторов. Возврат покупателю и отмена комиссии не удерживают. Начисление, выплата и запись в отдельный журнал выполняются транзакционно и защищены блокировкой сделки от повтора.

В `/admin?section=guarantor` ставку можно установить от 0 до 100% с точностью до сотых; каждое изменение сохраняется в журнале аудита. Там же показаны последние начисления с исходной суммой, процентом, комиссией и выплатой продавцу. Перед включением этой версии применить `018_guarantor_fee.sql`. Локальные проверки и UI-моки не заменяют отдельную проверку миграции и расчёта на тестовой базе MySQL.

## Резерв USDT

Баланс кошелька хранит общий остаток, `locked_balance` — его заблокированную часть; доступно для новых операций только `balance - locked_balance`. Гарант блокирует сумму при нажатии покупателем «Зарезервировать», при успешной выплате списывает её с общего баланса и снимает блокировку, а при возврате только снимает блокировку. P2P резервирует монеты продавца атомарно при открытии сделки из объявления; завершение переводит USDT, отмена снимает резерв. Проверка не даёт использовать уже зарезервированные биржей или другой сделкой USDT.

Та же миграция 018 восстанавливает общий баланс для уже открытых гарантийных и P2P-сделок, которые раньше учитывали резерв через уменьшение `balance`. Сами объявления SELL не резервируют весь объём до появления контрагента; реальный резерв создаётся при открытии сделки, и тогда повторно проверяется доступный остаток.
