# Treasury collection wallets and policy

Migration 031 creates separate TRON/USDT and Solana/SOL vault records, manual/threshold policy, and audit trail. Creating wallets twice returns the original addresses. Keys are encrypted with existing wallet encryption using AAD `0:TREASURY:TRON` and `0:TREASURY:SOLANA`. Never return encrypted keys or secrets through APIs. Back up the database together with WALLET_ENCRYPTION_KEY; database loss loses custody access.

Only full administrators may call /admin/treasury-collection, /wallets (POST), and /:network (PATCH). Helpers must remain denied. Default thresholds are 100 USDT and 1 SOL; default mode is manual. These are configurable policy defaults, not an estimate of economical network fees.

Migrations 032/033 enable the executor. Manual: preview, then explicit confirmation within 60 seconds. Threshold: the worker scans every 30 seconds and queues a plan only when the sum of ready, reconciled sources reaches the saved threshold. Sources are scanned in pages of 50 with a persisted cursor. Policy includes a minimum source amount and maximum network expense. Set TREASURY_COLLECTION_PAUSED=true to stop new signing; previously signed transactions still reconcile. Deployment must keep both modes manual until the operator explicitly enables threshold execution in the new UI.

Only direct deposit fees and finalized Pump launch fees are attributable in this release. Accounts with P2P, escrow or internal-transfer history in TRON are deliberately blocked pending provenance reconstruction. Unexplained on-chain surpluses, deficits, AML-held deposits, active swaps, withdrawals and reservations also block a source. The chain asset balance must equal the complete customer liability plus explicitly earned and uncollected fees, exactly in atomic units. Treasury global availability subtracts already collected proceeds and active job reservations. Unsupported history is not silently swept.

Only one batch per network can be active. Queued jobs reserve treasury availability but do not lock customer wallets. Immediately before processing each source, the worker locks its wallets in SQL. wallets_collection_guard rejects concurrent changes to balances, reserves, addresses or keys until settlement/cancellation; balances are never debited by the collection engine. Customer activity on a source is temporarily unavailable during this phase. A unique active source slot and worker advisory lock serialize execution. A signed transaction is persisted before broadcast. Unknown results only replay identical signed bytes. SOL expiration requires finalized block-height and history checks. TRON receipt ambiguity retains the source lock for administrator review; there is no unsafe force-unlock endpoint. Recheck/cancel serialize with the executor. An unsigned job can cancel only when there is no outstanding gas grant. Confirmed failed transfers impose a one-hour source cooldown to limit repeated network expenses.

TRON operational gas must be funded by the operator sending TRX to the treasury TRON address. The engine grants only the estimated budget to the source, reserving up to 3 TRX per gas-grant transfer. Grants are durably signed, confirmed, excluded from customer deposits, and tracked separately from customer TRX and treasury profit. Unused source gas is reused. If exact estimation is unavailable before account activation, the configured maximum is the disclosed conservative reserve; final USDT construction must fit this budget. Confirmed fees never use client TRX. Insufficient gas funds block the job without a USDT transfer. SOL network fees come only from earned SOL, reduce net proceeds and treasury book balance once. Consolidation moves custody, not profit; treasury principal is not charged again.

Admin history shows collection hashes, gas-grant hashes, actual expense and blocked/review reasons. /:network/preview, /plans/:id/execute, /jobs/:id/cancel and /jobs/:id/recheck are under /admin/treasury-collection. They are administrator-only. Failed/expired jobs release guards after trustworthy reconciliation; ambiguous ones remain held. No funded mainnet transfer is performed by release checks. Funded end-to-end verification remains an explicit operator action. Current automated tests and isolated SQL migration/guard checks do not prove live transfer completion.
